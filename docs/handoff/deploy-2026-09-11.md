### [HARD] 배포 순서 제약

**`7912636` 을 단독으로 배포하지 않는다.** 현재 배포본은 종료코드를 보지 않고 stdout 을 채택한다. `7912636` 만 올리면 편재하는 SIGABRT(134) 때문에 **mail-triage 전건이 실패로 전환**된다. 반드시 `27aae3d` 와 함께 나가야 한다.

지금은 둘 다 `main` 에 있으므로 **`main` 을 통째로 배포하면 이 제약은 자동으로 충족**된다. 부분 배포·체리픽만 하지 않으면 된다.

## 4. 환경 변수 — `GROWTH_REPORTS_DIR` [필수]

#103 동기화 엔드포인트가 **생산자와 같은 디렉터리**를 보게 해야 한다. 설정하지 않으면 배포본 기본값이 `/opt/reports` 를 가리켜, 고치려던 "조용한 0건" 이 API 에서 그대로 재현된다.

```bash
sudo systemctl edit hermes-api-server      # 드롭인 편집기
```

편집기에 아래를 넣는다. 경로는 **리포트를 실제로 생성하는 체크아웃**이다.

```ini
[Service]
Environment=GROWTH_REPORTS_DIR=/home/abyz-lab/work/workspace-github/holee9/ra-hermes-multi-agent/reports
```

확인:

```bash
ls -d /home/abyz-lab/work/workspace-github/holee9/ra-hermes-multi-agent/reports
ls /home/abyz-lab/work/workspace-github/holee9/ra-hermes-multi-agent/reports/growth-*.json | tail -3
```

## 6. 검증 (순서대로)

```bash
KEY=<API_SERVER_KEY>          # 값은 출력하지 말 것

# 6-1 health
curl -s -o /dev/null -w '%{http_code}\n' http://localhost:8643/health        # 기대 200

# 6-2 입력 검증 — 500 이 아니라 400 이어야 한다 (2ce314c·876f602)
curl -s -o /dev/null -w '%{http_code}\n' -X POST http://localhost:8643/v1/chat/completions \
  -H "Authorization: Bearer $KEY" -H 'Content-Type: application/json' \
  -d '{"messages":[{"role":"user","content":123}]}'                          # 기대 400
curl -s -o /dev/null -w '%{http_code}\n' -X POST http://localhost:8643/v1/chat/completions \
  -H "Authorization: Bearer $KEY" -H 'Content-Type: application/json' -d '[1]'   # 기대 400

# 6-3 #103 엔드포인트 — dir_exists 가 true 여야 한다 (4번 설정이 먹었는지)
curl -s http://localhost:8643/v1/growth/reports -H "Authorization: Bearer $KEY" \
  | python3 -c 'import sys,json; d=json.load(sys.stdin); print("dir_exists=",d.get("dir_exists"),"count=",d.get("count"),"dir=",d.get("reports_dir"))'
# 기대: dir_exists= True, count>0
```

`dir_exists=False` 가 나오면 4번 경로가 틀린 것이다. 재기동 전에 경로를 고친다.

### 6-4 최종 증거 — n8n 실제 메일 1건
