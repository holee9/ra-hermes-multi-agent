## 1. 사전 확인

`git fetch` 는 원격 추적 ref 만 갱신하고 **작업 트리의 HEAD 를 옮기지 않는다.** 배포는 작업 트리 파일을 복사하므로, 확인해야 할 것은 원격이 아니라 **지금 체크아웃된 HEAD** 다.

```bash
cd ~/work/workspace-github/holee9/ra-hermes-multi-agent
git fetch origin main
git log --oneline -1                       # 지금 배포될 커밋 — 3906368 이상이어야 한다
git rev-list --count --left-right origin/main...HEAD
#   0 0  = 원격과 동일 (정상)
#   N 0  = 원격이 앞섬 -> `git pull --ff-only` 로 맞춘 뒤 다시 확인
git status --short                         # 배포 대상 파일에 미커밋 변경이 없어야 한다
```

## 2. 백업 (12파일 매니페스트)

**실패하면 실제로 멈춰야 한다.** `echo` 만 하는 경고는 다음 줄을 막지 못하고, `set -u` 는 미정의 변수만 잡지 명령 실패를 잡지 않는다. 그래서 백업은 **스크립트 파일로 실행**한다 — `exit` 가 동작해야 "백업 실패 시 배포 불가" 가 성립한다.

아래를 그대로 붙여 넣어 스크립트를 만든다.

```bash
cat > /tmp/ra-backup.sh <<'SCRIPT'
#!/usr/bin/env bash
set -euo pipefail

SRC=/opt/hermes-ra
STAMP=$(date +%Y%m%d-%H%M%S)
BACKUP="${SRC}/.backup-${STAMP}"

sudo mkdir -p "${BACKUP}/scripts"
sudo cp -a "${SRC}/hermes-api-server.py" "${SRC}/ra_citation_lint.py" "${BACKUP}/"
sudo cp -a "${SRC}/scripts/." "${BACKUP}/scripts/"

# 내용 검증 — 개수가 아니라 **바이트 단위 동일성**을 본다.
# diff 는 다르면 0 이 아닌 코드로 끝나고, set -e 가 여기서 중단시킨다.
sudo diff -r "${SRC}/scripts" "${BACKUP}/scripts" >/dev/null
sudo diff "${SRC}/hermes-api-server.py" "${BACKUP}/hermes-api-server.py" >/dev/null
sudo diff "${SRC}/ra_citation_lint.py"  "${BACKUP}/ra_citation_lint.py"  >/dev/null

# 드롭인(환경 설정)도 함께 보존한다 — 4번에서 건드리므로 롤백 범위에 포함되어야 한다.
if [ -d /etc/systemd/system/hermes-api-server.service.d ]; then
  sudo cp -a /etc/systemd/system/hermes-api-server.service.d "${BACKUP}/dropin.d"
fi

echo "BACKUP=${BACKUP}"
SCRIPT
chmod +x /tmp/ra-backup.sh
```

실행하고, **종료코드가 0 일 때만 다음 단계로 간다.**

```bash
bash /tmp/ra-backup.sh && echo "백업 검증 통과 — 배포 진행 가능" \
                       || echo "*** 백업 실패 — 배포하지 말 것 ***"
```

출력된 `BACKUP=...` 경로를 **적어 두고**, 같은 셸에서 이어서 쓸 것이면 변수로 넣는다.

```bash
export BACKUP="/opt/hermes-ra/.backup-20260911-000000"   # 위에서 출력된 실제 STAMP 로 바꿀 것
ls -la "$BACKUP"
```

> 새로 추가되는 파일(예: 배포본에 없던 스크립트)은 백업 대상이 아니다 — 원본이 없기 때문이다. 롤백은 **기존 파일의 이전 내용 복원**까지만 보장하며, 신규 파일은 롤백 후에도 남는다. 문제가 되면 7번에서 수동으로 지운다.

`deploy-local.sh` 는 설치 전에 임시 디렉터리에서 진입점 import 를 먼저 검증한다(#139). 여기서 실패하면 설치하지 않고 멈추므로, 실패 메시지를 그대로 보고 중단하면 된다.

**다만 일부 파일을 SKIP 하고도 종료코드 0 으로 끝날 수 있다.** 종료코드만 보지 말고 출력의 `SKIPPED` 목록을 읽고, 아래로 **목적지 파일이 실제로 갱신됐는지** 대조한다.

```bash
# 저장소 원본과 배포된 파일의 해시가 같은지 12개 전부 대조
for f in hermes-api-server.py ra_citation_lint.py peer-comment-poller.py knowledge_fetch.py \
         index_github_repos.py index_ra_knowledge.py nas_indexer_v2.py growth-metrics.py \
         meta_extractor.py extract_mail_qa.py; do
  a=$(sha256sum "scripts/$f" 2>/dev/null | cut -d' ' -f1)
  b=$(sudo sha256sum "/opt/hermes-ra/scripts/$f" 2>/dev/null | cut -d' ' -f1)
  [ -n "$a" ] && [ "$a" = "$b" ] && echo "OK   $f" || echo "DIFF $f  (repo=${a:0:8} target=${b:0:8})"
done
for f in hermes-api-server.py ra_citation_lint.py; do
  a=$(sha256sum "scripts/$f" | cut -d' ' -f1)
  b=$(sudo sha256sum "/opt/hermes-ra/$f" 2>/dev/null | cut -d' ' -f1)
  [ "$a" = "$b" ] && echo "OK   root/$f" || echo "DIFF root/$f"
done
```

`DIFF` 가 하나라도 나오면 재기동하지 말고 원인을 먼저 확인한다.

### 6-4 최종 증거 — n8n 실제 메일 1건

위 6-1~6-3 은 배포가 붙었다는 증거이고, **mail-triage 가 실제로 동작한다는 증거는 n8n 실제 메일 1건이 통과하는 것**이다. 그 전까지는 "배포됨" 이지 "동작 확인됨" 이 아니다.

**6-2 의 curl 400 은 n8n 의 오류 흐름 증거가 아니다.** 서버가 400 을 돌려준다는 사실만 보여 준다. n8n 이 400 을 만났을 때 재시도하는지·중단하는지·Yellow 로 보내는지는 **미검증**이며, 그 확인은 실제 워크플로 실행에서만 가능하다. 정상 메일은 `content` 가 문자열이라 이 경로에 걸리지 않는다.

## 7. 롤백

셸이 끊겨 `BACKUP` 이 비어 있으면 `${BACKUP}/hermes-api-server.py` 가 `/hermes-api-server.py` 로 해석된다. **빈 값이면 중단하는 가드를 먼저 둔다.**

```bash
# 셸이 바뀌었으면 2번에서 적어 둔 경로를 다시 넣는다
: "${BACKUP:=}"
[ -n "$BACKUP" ] && [ -f "$BACKUP/hermes-api-server.py" ] || {
  echo "*** BACKUP 이 비었거나 백업 파일이 없다. 롤백 중단 ***"
  ls -d /opt/hermes-ra/.backup-* 2>/dev/null | tail -3    # 후보 경로 확인
  return 2>/dev/null || exit 1
}

sudo cp -a "$BACKUP/hermes-api-server.py" "$BACKUP/ra_citation_lint.py" /opt/hermes-ra/ \
  && sudo cp -a "$BACKUP/scripts/." /opt/hermes-ra/scripts/ \
  && { [ -d "$BACKUP/dropin.d" ] && sudo cp -a "$BACKUP/dropin.d/." \
         /etc/systemd/system/hermes-api-server.service.d/ || true; } \
  && sudo systemctl daemon-reload \
  && sudo systemctl restart hermes-api-server \
  && curl -s -o /dev/null -w '%{http_code}\n' http://localhost:8643/health \
  || echo "*** 롤백 실패 — 수동 확인 필요 ***"

# 복원 확인 — 백업과 현재가 동일해야 한다
sudo diff -r "$BACKUP/scripts" /opt/hermes-ra/scripts >/dev/null && echo "scripts 복원 확인" \
  || echo "*** scripts 불일치 ***"
```
