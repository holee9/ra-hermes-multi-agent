## 1. 무슨 일이 있었나 — 확인된 사실

2026-09-10, Codex 가 #150 에 협업 차단을 기록했고([`5617027085`](https://github.com/holee9/ra-hermes-multi-agent/issues/150#issuecomment-5617027085), 10:18:52Z) 상태와 재개 조건을 남겼다. 이후 Codex 가 스스로 재검증해 판정 근거를 정정했다(`5627060437`).

| 시각 (UTC) | 사건 | 출처 |
|---|---|---|
| 10:13:04.382 | Claude 의 Bash 호출 `toolu_01AMvszGGCR11g7je5oDShGe` 발신 | Claude 세션 transcript (Codex 대조) |
| 10:18:52 | Codex 가 `blocked` 로 전환하고 #150 에 기록 — 요청 후 **5분 48초** | 댓글 `5617027085` |
| 10:27:17.400 | 같은 호출의 tool_result 도착 — 요청 후 **14분 13초**, 정상 결과 | Claude 세션 transcript (Codex 대조) |

즉 **지연은 사실이나 영구 미응답은 아니었다.**

정확히 무엇이 결함이었는지는 원문을 그대로 읽어야 한다. `5617027085` 은 **"프로세스 종료나 작업 실패를 단정하는 것은 아닙니다"** 라고 명시했다. 따라서 "상대가 죽었다고 단정했다" 는 것은 그 댓글에 대한 부당한 요약이며, 이 문서의 초안이 그렇게 적었던 것을 정정한다.

실제 결함은 두 가지다.

- **범위 확대** — 하나의 도구 호출 대기를 **협업 전체의 `blocked`** 로 승격했다. 막힌 것은 그 호출 하나였다.
- **재개 경로 부재** — 재확인 주기도, 그 사이에 독립 리뷰를 계속할 경로도 없이 멈췄다. 그래서 5분 48초의 대기가 **이후 리뷰 미응답으로 이어졌다**. (별도 사실: PR #151 의 마지막 Codex 리뷰 댓글은 08:51:22Z 이며, 이는 blocked 시각 10:18 과 다른 기준점이므로 침묵 길이를 하나로 합산하지 않는다.)

### 1.1 조사 과정에서 Claude 가 낸 두 번째 오류 — 같은 결함의 반복

Claude 는 이 사안을 조사하면서 `since=2026-09-10T22:50:00Z` 로 #150 댓글을 조회하고 **"차단 기록이 존재하지 않는다"** 고 결론냈다. 그 창은 10:18 사건을 통째로 배제한다. 기록은 처음부터 있었다.

두 오류의 모양이 같다. **불완전한 관측 창에서 얻은 음성 신호를 확정으로 바꾼 것**이다. Codex 는 5분 48초짜리 창의 무응답을 협업 전체 차단으로, Claude 는 잘못 고른 시간 창의 무결과를 "기록 없음" 으로 승격했다. 이 문서가 막으려는 것은 그 한 가지다.

## 2. 근본 원인

1. **부재 증거를 확정으로 승격** — 관측되지 않은 것은 없는 것이 아니다. 창이 좁거나 어긋나면 진행 중인 것도 멈춘 것으로 보인다.
1-1. **국소 대기를 전역 차단으로 확대** — 막힌 것이 호출 하나일 때 협업 전체를 세우지 않는다. 막히지 않은 일은 계속한다.
2. **신원 미구분** — 두 에이전트가 같은 GitHub 계정(`holee9`)으로 댓글을 쓴다. 작성자 필드로 Claude 와 Codex 가 구분되지 않아 사후에 누가 무엇을 기록했는지 원장에서 복원되지 않는다.
3. **요청별 상태 부재** — 리뷰 요청이 전달됐는지, 받았는지, 처리 중인지, 끝났는지가 원장에 남지 않아 복귀한 쪽이 무엇이 밀렸는지 재구성하지 못한다.

## 3. Claude 가 적용한 것 (단독 적용 범위)

- **발신자 태그** — 협업 댓글 첫 줄에 `[Claude]` 와 corr id 를 붙인다. 다만 이는 **자가 표시이지 인증이 아니다**(§4 6행). 계정이 같은 한 위조 불가성은 주장하지 않는다.
- **관측 창 규율** — 기록 존재 여부를 판단할 때 추측한 `since` 를 쓰지 않는다. 전체를 수집한 뒤 시간으로 거른다(§5). 좁은 창의 음성 결과로 "없음" 을 결론내지 않는다.
- **차단 호출 시간·출력 제한** — 모든 블로킹 명령에 명시적 타임아웃을 걸고 출력을 `--jq` 등으로 경계 짓는다.
- **작업 전 흔적** — 오래 걸리는 작업은 시작 **전에** 무엇을 시작하는지 남긴다. 중간에 멈춰도 진단 가능해진다.

## 4. 양자 조항 — Codex 지적 반영

| # | 조항 | 내용 |
|---|---|---|
| 1 | 전달 ≠ 수신 | **소켓 송신 성공은 수신 ACK 가 아니다.** 보냈다는 사실로 상대가 받았다고 판단하지 않는다 |
| 2 | 미반환 ≠ 정지 | **pending result 는 hang 이 아니다.** 결과를 관측하지 못한 것과 세션이 멈춘 것은 다른 사건이다 |
| 3 | 교차 확인 의무 | 차단 선언 **전에** 최신 GitHub 댓글, 원격 HEAD, 상대 세션 진행 흔적을 교차 확인한다 |
| 4 | HEAD 전진의 한계 | **원격 HEAD 가 전진했다는 사실만으로 특정 동료의 생존을 단정하지 않는다.** 다른 작성자일 수 있다. 생존 근거로 쓰려면 **세션 귀속과 시각이 붙은 진행 증거**여야 한다 |
| 5 | 관측 불명은 unknown | 판정할 수 없으면 `unknown` 으로 남기고 단정하지 않는다. 그 상태에서도 독립 리뷰는 계속한다 |
| 6 | 신원 태그의 한계 | 발신자 태그는 **자가 표시이며 인증이 아니다.** 신원 확인이 필요한 판단의 유일한 근거로 삼지 않는다 |
| 7 | 시간 제한 진단 | 진단에 시간 상한을 두고, 복구 후에는 **미응답 요청 목록을 재수집해** 순서대로 처리한다 |
| 8 | 차단은 국소로 적는다 | `BLOCKED` 는 **막힌 대상 하나를 지목**한다. 협업 전체를 세우지 않는다. 선언에는 재확인 시각과 "그 사이 독립 리뷰는 계속한다"는 명시가 함께 들어간다 |

### 4.1 요청별 상태 추적

임의 운영 상수(예: "60분")를 쓰지 않는다. 대기 시간은 **요청마다 합의한 값**을 명시한다.

각 리뷰 요청은 첫 줄에 corr id 와 상태를 싣는다. 상태는 `pending` → `ack` → `progress` → `done`.

```
[Claude][corr:<id>][pending] 리뷰 요청 — <대상 커밋>
check_at: 2026-09-11T02:00Z    # 이 요청에 대해 합의한 확인 시각
```

- 요청자는 `check_at` 을 제안하고, 수신자는 `ack` 에서 수용하거나 다른 값을 제시한다. 합의 전에는 어느 쪽도 상대를 지연으로 판정하지 않는다.
- `check_at` 을 지나도 `ack` 가 없으면 요청자는 `unknown` 으로 기록하고(단정 금지) **되돌릴 수 있는 작업만** 단독 진행한다. 배포·파괴적 작업·사람 승인 사안은 해당하지 않는다.
- 복귀한 쪽은 **미응답 요청 목록을 먼저 재수집**해 원장에 남기고 순서대로 처리한다.
- 동료 메시지는 **사람 승인이 아니다.** 이 규약은 그 경계를 바꾸지 않는다.

역할은 그대로다. Claude 가 구현, Codex 가 독립 리뷰·재검증이다.

## 5. 검증 방법

기록 존재 여부는 **전체 수집 후 시간 필터**로 확인한다. 첫 페이지는 최신이 아니다.

```bash
# 옳음 — 시간 상한을 걸고 전량 수집한 뒤 시간으로 거른다
timeout 30s gh api --paginate \
  "repos/holee9/ra-hermes-multi-agent/issues/150/comments" \
  --jq '.[] | select(.created_at > "2026-09-10T00:00:00Z") | "\(.created_at) \(.body[:80])"'
echo "exit=$?"   # 0 이 아니면 아래 규칙이 적용된다

# 틀림 — per_page 첫 페이지는 최신 N 이 아니고, 추측한 since 는 사건을 배제한다
gh api "repos/.../issues/150/comments?per_page=20"
```

§1.1 의 오류가 정확히 아래쪽 형태에서 나왔다.

**수집 실패는 부재가 아니다.** 위 명령이 0 이 아닌 코드로 끝나거나(타임아웃·rate limit·네트워크) 페이지네이션이 중간에 끊기면, 그 결과로 **"기록 없음" 을 판정하지 않는다.** `unknown` 으로 남기고 재시도하거나 상대에게 확인한다. 판정에 쓸 수 있는 것은 **완주한 수집**뿐이다.

## 6. 이 문서가 하지 않는 것

- 세션 간 새 채널을 만들지 않는다. Claude 의 통신 상대는 `codex-reviewer` 하나이며 회신 원장은 #150 댓글이다.
- 게이트를 바꾸지 않는다. WP close/reopen 사람 전용, n8n 변경 사전 보고, KB 레포 읽기 전용은 그대로다.
- 신원 인증을 제공하지 않는다(§4 6행).
